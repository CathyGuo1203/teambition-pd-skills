# 项目计划验证器 (Project Plan Validator)

## 触发场景

当用户提供 Teambition 导出的项目计划 Excel 文件，并要求：
- "给这个计划生成 WBS 编号"
- "检查一下这个计划的时间安排是否合理"
- "帮我验证一下项目计划的逻辑"
- "看看有没有时间冲突的任务"
- "分析这个 WBS 结构是否合理"

## 快速开始

### 输入要求

用户提供 Excel 文件，必须包含以下列：
- **标题**: 任务名称
- **任务层级**: 数字（1 表示根任务，2 表示子任务，依此类推），如无此列会自动根据"父任务"列推断
- **开始时间**: 日期时间格式（可选，但建议提供）
- **截止时间**: 日期时间格式（可选，但建议提供）
- **父任务**: 父任务的标题（可选，用于父子关系检查和层级推断）

### 使用方式

```bash
# 基础用法
python scripts/wbs_generator.py <输入文件.xlsx> [输出目录]

# 示例
python scripts/wbs_generator.py 计划管理导出明细.xlsx
python scripts/wbs_generator.py /path/to/plan.xlsx ./output/
```

## 功能说明

### 1. WBS 编号生成

自动生成符合层级规范的 WBS 编号：
- 支持最多 4 层级（如 `1.1.1.1`）
- 在 Excel 最左侧插入"序号"列
- 严格遵循父子继承关系
- 如无"任务层级"列，会根据"父任务"列自动推断

**编号规则**:
- 根任务：1, 2, 3, ...
- 一级子任务：1.1, 1.2, 1.3, ..., 2.1, 2.2, ...
- 二级子任务：1.1.1, 1.1.2, ..., 1.2.1, 1.2.2, ...
- 三级子任务：1.1.1.1, 1.1.1.2, ...

### 2. 时间逻辑检查（4 项）

#### 检查 1: 时间字段完整性
- ✅ 验证每个任务的开始时间和截止时间是否填写
- ⚠️ 标记完全缺失时间信息的任务
- 📋 输出缺失时间的任务清单

#### 检查 2: 父子任务时间逻辑
- ✅ 子任务开始时间 ≥ 父任务开始时间
- ✅ 子任务结束时间 ≤ 父任务结束时间
- ❌ 检测时间冲突并输出详细列表

#### 检查 3: 同层级子任务时间顺序
- ✅ 前一个任务的结束时间 ≤ 后一个任务的开始时间
- ⚠️ 检测时间重叠/倒序（并行任务会触发此警告）
- 📊 统计重叠天数，输出前 20 个示例

#### 检查 4: 时间范围有效性
- ✅ 截止时间 ≥ 开始时间
- ❌ 检测时间范围为负的任务

### 3. 生成验证报告

自动生成 Markdown 格式的验证报告，包含：
- 📊 总体结论汇总表
- 🔍 4 项检查的详细结果
- 📈 问题根源分析
- 💡 改进建议
- 📋 下一步行动指南

如需 Word 格式报告，可使用 `dws` 技能进行格式转换。

## 输出文件

处理后生成两个文件：

1. **`{原文件名}_WBS.xlsx`**: 添加了 WBS 编号列的 Excel 文件
2. **`{原文件名}_验证报告.md`**: Markdown 格式的验证报告

## 典型问题模式

### 模式 1: 批量导入数据（最常见）
**特征**:
- 80% 以上任务存在时间重叠
- 所有任务的开始/结束时间相同或高度集中
- WBS 编号是层级化的，但时间是平行的

**原因**: 从 Teambition 批量导出时，时间字段可能是默认值或占位符

**建议**: 使用 `teambition-project-planner` 技能重新排期

### 模式 2: 部分任务缺失时间
**特征**:
- 少数任务（<5%）的开始和截止时间都为空
- 其他任务时间正常

**原因**: 这些任务可能是模板任务或尚未规划的任务

**建议**: 根据实际工作计划补充时间字段

### 模式 3: 父子时间冲突
**特征**:
- 子任务超出父任务的时间范围
- 通常是手动调整导致的疏忽

**建议**: 调整子任务时间或扩大父任务时间范围

### 模式 4: 真实并行任务
**特征**:
- 同一父任务下的多个子任务时间重叠
- 但这些任务确实可以并行执行（如不同负责人）

**建议**: 这是合理的，无需调整。可在报告中注明"并行任务组"

## 与相关技能的协作

### teambition-project-planner

**工作流**:
1. 使用 `project-plan-validator` 检查现有计划
2. 根据验证报告发现问题

4. 再次验证调整后的计划

**典型对话**:
```

→ 运行 teambition-project-planner，基于 WBS 结构和依赖关系生成新计划
```

## 最佳实践

### 1. 定期验证
- 每次从 Teambition 导出后都运行一次
- 在项目关键节点（如 Gate Pass 前）重点检查
- 发现大量问题时及时重新排期

### 2. 解读报告
- **问题数 = 0**: 计划逻辑自洽，可以执行
- **问题数 < 10**: 少量问题，手动调整即可
- **问题数 > 50**: 大量问题，建议重新排期
- **重叠率 > 70%**: 批量导入数据，需要真实排期

### 3. 排期策略
根据验证结果选择策略：

**A. 串行任务组**（必须按顺序）
- 如：DD 计划书发行 → DD 开始判断会 → DD 达成度确认会
- 重新排期：每个任务 3-5 个工作日，确保不重叠

**B. 并行任务组**（可以同时推进）
- 如：材料开发、DTS、供应商开发（不同负责人）
- 保持现状，在报告中注明"并行任务"

**C. 里程碑任务**（关键节点）
- 如：Gate Pass 会议、项目批准
- 放在所有前置任务完成后，设置为单日任务

## 常见问题

### Q1: 为什么我的任务都显示时间重叠？
**A**: 这通常是因为从 Teambition 导出时，所有任务使用了相同的默认时间。需要使用 `teambition-project-planner` 技能进行真实排期。

### Q2: WBS 编号生成错了怎么办？
**A**: 检查 Excel 中的"任务层级"列是否正确。根任务应为 1，子任务为 2，依此类推。如果层级错误，修正后重新运行脚本。

### Q3: 如何区分并行任务和异常重叠？
**A**: 
- **并行任务**: 不同负责人、不同工作内容、可以同时进行
- **异常重叠**: 同一负责人、有依赖关系、应该按顺序执行

查看验证报告中的"问题分析"部分，会根据重叠模式给出判断建议。

### Q4: 可以只生成 WBS 不检查时间吗？
**A**: 可以。脚本会同时执行两项功能，但你可以只使用 WBS Excel 文件，忽略验证报告。

### Q5: 支持多少个层级的 WBS？
**A**: 目前支持最多 4 层级（如 `1.1.1.1`）。如果需要更多层级，可以修改 `scripts/wbs_generator.py` 中的 `generate_wbs_numbering` 函数。

## 故障排除

### 错误 1: "缺少必要列：['标题']"
**原因**: Excel 文件格式不符合要求  
**解决**: 确保包含"标题"列，列名必须完全匹配

### 错误 2: "读取文件失败：..."
**原因**: 文件损坏或格式错误  
**解决**: 重新从 Teambition 导出，确保是 `.xlsx` 格式

### 错误 3: "ModuleNotFoundError: No module named 'pandas'"
**原因**: 缺少依赖库  
**解决**: 运行 `pip install pandas openpyxl python-docx`

### 错误 4: 报告中文乱码
**原因**: 文件编码问题  
**解决**: 脚本已设置 `encoding='utf-8'`，如仍有问题请检查系统 locale 设置
